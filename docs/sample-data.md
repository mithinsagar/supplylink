# The sample dataset

Generated by `scripts/generate_sample_data.py` from a fixed seed, so the demo
produces identical numbers on every machine and the figures quoted in the README
are the figures a reviewer actually sees.

```bash
python scripts/generate_sample_data.py
```

## What it contains

| File | Rows | Role |
| --- | --- | --- |
| `data/samples/erp/erp_master_*.csv` | 99 | The landing zone — *the current extract* |
| `data/samples/erp_extracts/erp_master_2026-03-01.csv` | 99 | Archive: first extract |
| `data/samples/erp_extracts/erp_master_2026-03-14.csv` | 99 | Archive: second extract, with real changes |
| `data/samples/acme/acme_catalogue_*.csv` | 62 | Supplier drop — the messy feed |
| `data/samples/globalparts/catalog.json` | 45 | Served by the vendor API simulator |
| `data/reference/suppliers.csv` | 10 | Reference data |
| `data/malformed/*.csv` | — | Structurally broken files, for run-level failure tests |

98 products across 9 categories, supplied by 10 suppliers.

**The landing zone versus the archive.** `samples/erp/` holds *the current
extract*, the way a real landing zone does: each night's file supersedes the
last, and the pipeline reads whatever is there. `samples/erp_extracts/` keeps
both so the demo can stage them in sequence and show SCD-2 doing its job.

## The three dialects

The same product, as each system writes it:

| | ERP | ACME | GlobalParts |
| --- | --- | --- | --- |
| Identifier | `WM-001` | `wm001` | `wm_001` |
| Name | `Wireless Mouse` | `wireless mouse` | `Wireless Mouse` |
| Category | `Electronics` | `electronics` | `ELEC` |
| Price | `"799.00"` | `"799"` | `799.0` |
| Supplier | `SUP-042` | `SUP42` | `SUP042` |
| Lifecycle | `ACTIVE` | *(absent)* | `LIVE` |

All three map to one canonical record. The ERP also pads some names with runs of
spaces, as fixed-width exports do — `collapse_whitespace` absorbs that, and
without it every padded name would look like a rename on every run.

## Planted defects

Every one is deliberate and exercises a specific mechanism.

| Defect | Where | Exercises |
| --- | --- | --- |
| Negative inventory | ACME (~7 rows), ERP (1), vendor (4) | `min` rule — the largest failure category |
| Unknown supplier | ACME (5), ERP (1), vendor (3) | referential integrity against `core.suppliers` |
| Duplicate SKU | ACME (2), ERP (1) | batch-scoped `unique` |
| Invalid currency (`RS`, `RUPEE`) | ACME (1), ERP (1) | `allowed_values` |
| Missing required field | ACME (1), ERP (1) | `required` |
| Non-numeric price (`n/a`) | ACME (1) | type coercion failure |
| Unknown category (`widgets`, `MISC`) | ACME (1), vendor (1) | lookup miss → null → `required` |
| Zero price with stock | ACME (1) | the `stocked_items_must_be_priced` business rule |
| Discontinued with stock | ERP (several) | a **warning** — recorded, record still loads |
| Thousands separator, currency symbol | ACME (2) | `to_decimal` tolerance |
| Ragged rows, bad encoding, missing headers | `data/malformed/` | run-level failures |

## Changes between the two ERP extracts

The second extract moves stock on nearly every row and changes exactly five
tracked attributes. That contrast is the SCD-2 demonstration:

| SKU | What changed |
| --- | --- |
| `MN001` | price 24,999 → 27,499 |
| `CB004` | price 499 → 549 |
| `KB001` | renamed to "Mechanical Keyboard TKL Hot-Swap" |
| `SD002` | re-sourced from `SUP-021` to `SUP-034` |
| `NW002` | `ACTIVE` → `DISCONTINUED` |

Result: **5 updated, 89 unchanged**. The 89 all have different stock levels and
produce no new version, because quantity is a measure rather than a tracked
attribute.

## Multi-source behaviour

Running all three feeds shows precedence at work:

| Source | Precedence | Inserted | Unchanged | Superseded |
| --- | ---: | ---: | ---: | ---: |
| `erp_core` | 10 | 94 | 0 | 0 |
| `acme_supplier` | 20 | 1 | 15 | 28 |
| `globalparts_api` | 30 | 1 | 30 | 4 |

ACME's 28 supersessions are correct, not a fault: ACME lower-cases product names,
so `Mechanical Keyboard TKL` arrives as `Mechanical Keyboard Tkl` and the casing
cannot be reconstructed. The ERP is more authoritative, so its values stand and
the disagreement is counted rather than applied. Meanwhile ACME contributes one
SKU the ERP feed could not supply — which is why the feed is ingested at all.

## Regenerating

The generator is deterministic. Changing it changes the demo's numbers, so
`SEED` should stay fixed unless the dataset is being deliberately reshaped.
